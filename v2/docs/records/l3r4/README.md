## After the owner has answered (the session or the integrator)

```
python3 v2/docs/records/l3r2/conditional/od_l3_N.py --option <option> --words "<his words>" --date <YYYY-MM-DD> [row extras]
   (each row in the order its prerequisites allow; ../l3r2/README.md, "Applying an owner's answer")
env -C v2/ecad/tools python3 rules_lib.py requirements
env -C v2/ecad/tools python3 rules_render.py --requirements
python3 v2/docs/records/l3r4/reissue.py --check || python3 v2/docs/records/l3r4/reissue.py
python3 v2/docs/handover/layer3/render_l3r2.py
```

Then the owner approves the change record by a ruling whose `decides` is `definition_reissue`, dated on or after every
row's ruling, and `l3r2.yaml`'s `definition_reissue` names `v2/docs/handover/layer3/DEFINITION-CHANGE-RECORD-L3.md` with
its sha256/16 and that ruling (`{record, sha16, approved_by}`); the renderer then reads L3-C26 CLOSED. Only after that
approval are the proposed texts written into `CONOPS.md` and `PRODUCT-BRIEF.md`, through their layers' review.

```
git checkout fnd/l3r4 -- v2/docs/records/l3r4 v2/ecad/tools/tests/test_l3r4.py v2/docs/handover/layer3/l3r2.yaml \
  v2/docs/records/README.md

env -C v2/ecad/tools/tests python3 run.py test_requirements test_l3r2 test_l3r4
```

If the set carries a different `CONOPS.md` or `PRODUCT-BRIEF.md` than the baselined texts `l3r2.yaml` names, the map and
the generator refuse; the passages are then located again on the new baseline before the answers are applied.

## After the owner has answered (the session or the integrator)

```
python3 v2/docs/records/l3r2/conditional/od_l3_N.py --option <option> --words "<his words>" --date <YYYY-MM-DD> [row extras]
   (each row in the order its prerequisites allow; ../l3r2/README.md, "Applying an owner's answer")
env -C v2/ecad/tools python3 rules_lib.py requirements
env -C v2/ecad/tools python3 rules_render.py --requirements
python3 v2/docs/records/l3r4/reissue.py
python3 v2/docs/handover/layer3/render_l3r2.py
```

`reissue.py` is run once the seven answers (six after a reject) are recorded, before the approval. The owner then approves the change record by
a ruling whose `decides` is `definition_reissue`, dated on or after every row's ruling, and `l3r2.yaml`'s
`definition_reissue` names `v2/docs/handover/layer3/DEFINITION-CHANGE-RECORD-L3.md` with its sha256/16 and that ruling
(`{record, sha16, approved_by}`); the renderer then reads L3-C26 CLOSED. **After the approval the generator is never run
to write:** only `python3 v2/docs/records/l3r4/reissue.py --check`, which compares the approved record to the sha
`definition_reissue` files and the draft to the sha the record names, so later changes to the registry leave them
current, and a write is refused. The proposed texts are written into `CONOPS.md` and
`PRODUCT-BRIEF.md` only after that approval, through their layers' review, with the rows the draft proposes added to
`handover/DEFINITION-STATUS.md`.

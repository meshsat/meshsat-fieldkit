# Board E5 (dock block): layout constraints

A view over the records at `main` `e3aedb25` (conventions and shared rules: [README.md](README.md)). Board E5 has no
schematic and no netlist: `gen_pcb_e5.py` (run by `build_e5.sh`, not by a chain) generates it from **board A's own board
file**, reading board A's nets by position under each spring pin (`boards/e5.json` `_table_why`, `_chain_why`). Its
board file is `686b29a734c55b9a`, and it is the one board of the seven whose deliverable folder passes the final gate
(`boards/e5.json` `_stackup_dk_why`). It is not at layout entry: 6 blocker lines (`CURRENT-EVIDENCE.md` lines 152 to
157: five re-takes and INT-001's coverage entry).

## 1. Stackup: DECIDED, two layers at 2 oz

- **2L-2oz** (owner ruling 7, 12 September 2026): 0.070 mm copper on both faces, 1.44 mm core. Nothing inner to weigh
  (`v2/docs/STACKUP-DECISIONS.md` section 3.7).
- **STK-001 residue:** the board file carries epsilon_r 4.6 where the row says 4.5 (the fabricator's two-layer figure);
  it closes with the re-cut of the deliverable folder and not alone, because rewriting the board would stale a folder
  that passes 21 of 21 (`boards/e5.json` `_stk001_residue_why`).
- Two-layer 2 oz floors: track and space 0.16 / 0.16 mm; solder-mask bridge 0.20 mm; PTH annular ring 0.254 mm
  (`jlcpcb-stackups-2026-09-25.md`, the 2 oz rows). Conformally coated, **masked at the targets**, which take the bare
  spacing column (README, "Spacing").

## 2. Power: the pack path through the contacts

- **What it carries** (`pcb_energy_chain.yaml` stage DOCK_BLOCK): the pack node from board E to board A through four
  CELL+ and four return Mill-Max spring pins in parallel, 9 A per pin, 36 A for the set, behind two 25 A blades.
- **At PWR-F12's 18 A for 60 s** (the chain stage the ruling's service current crosses): 4.5 A per pin if the four
  share equally (INFERRED), inside the pin's 9 A. The block's own copper from the wire lands to the four targets needs
  **11.95 mm on one 2 oz face, or 3.36 mm on each face if both share equally**, and **21 barrels of 0.4 mm drill** (or
  18 of 0.5 mm) wherever the path changes face (`calc/rail_widths.py`'s model applied to 18 A at 0.070 mm; the block
  has no intent file, so the table is not generated for it).
- The contact set is not the weakest stage (36 A against a 25 A fuse), which is the property the chain stage records.

## 3. Placement and geometry

1. **Every target's position is board A's**: the spring pins on board A's underside define the block, so any change to
   board A's pin placement regenerates E5; the two are checked together by `block_contract.py`, which writes
   `check_contracts_<letter>` from E5's board file and board A's (`CURRENT-EVIDENCE.md` line 155).
2. **Pack contacts and their returns adjacent, signal contacts on the far side** of the 43 x 26 mm field, so the 10 A to
   18 A loop stays small and away from the twelve signal targets (`pcb_emc.yaml` board e5).
3. **No analogue node of its own** (`pcb_sensitive.yaml` board e5): the Kelvin pair and thermistor that sense the pack
   are board P's; the twelve signal targets carry board A's nets and are declared on board A.
4. **No exposed conductor and no safety line** (`boards/e5.json` external_ports and safety_lines empty): TRN-001 reads
   PASS on the board file (awaiting revalidation).

## 4. What this layer cannot close for E5

- **INT-001 binding:** the coverage map reads `check_contracts`'s set verdict, which judges the six boards with a
  netlist and nothing of E5; the per-board verdict `block_contract.py` writes needs its entry in
  `pcb_rules_coverage.yaml` (the registry writer's), and binds only while board A's layout carries its netlist
  (`CURRENT-EVIDENCE.md` line 155).
- **The dielectric constant** (section 1), with the folder re-cut.
